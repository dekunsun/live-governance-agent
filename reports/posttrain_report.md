## 0. 总览：做了什么、学到了什么

### 总结

1. **【做了什么】**
   - a. 在一个合成的治理平台上实现了一个**只读的会话式 Agent**：模型通过只读工具查数、下钻、归因，输出带证据编号的结论卡片；格式、参数、编号校验、升级规则放在 Harness 和护栏，只把"在证据面前选主因"留给模型。
   - b. 把"合成世界 → 自动出题 → 确定性评分 → 规则引擎示范 → SFT → GRPO → 评测"整条链路跑通，每一步只改一件事，共 0.6B / 4B / 8B 三个模型、十余次 GPU 运行。
2. **【结果（合成数据）】**

   | 项 | 结果 | 说明 |
   |---|---|---|
   | 规则引擎版 | 标准答案题全对，幻觉 0 | 教师与参考答案 |
   | 4B 不训练 | 归因 3.6%，策略调整 16% | 7 类主因一次都没对 |
   | 4B 微调后（当前版本） | 归因 94%–96%，策略调整 91%–98%，幻觉 0，单题约 18 秒 | 194 + 150 题，两个种子，LoRA 2 epoch，归因 + 策略调整示范混合 |
   | 8B 同样数据 | 归因 96% | 只多对 4 题 |
   | GRPO v2，3 种子 | 归因 +4 / +1 / 0 题，策略调整 +3 / +7 / +17 题 | 收益远小于改示范 |
   | 前沿模型不训练（API 基线） | Qwen3.5-397B 零样本归因 61%，主因 77%，幻觉 0 | 同一 harness 和评分器；差在升级口径、流程规则和回合纪律，不是工具使用（第 17 节） |

3. **【结论】** 先修 Harness、再补示范、最后才是 RL，三者性价比差一个数量级；4B 够用；单次运行有波动（约 ±8 题，主要来自只有 16 题的"误判率上升"类），门槛按多种子中位数定。评测环境（工具 + 任务 + 评分器）本身可复用于模型侧。九条展开的结论见下文。
4. **【还没解决的】** 分数只衡量"与规则引擎一致"，真实数据上的验证是上线前的门槛；"误判率上升"类的归因波动大，要单独扩测试题；训练没见过的问法下"新建还是修改"的判断因种子而异；RL 的探针集要扩到 96 题以上才能用来选最终版。

### 九条主要结论

1. **链路是通的，而且便宜。** 合成世界 → 自动出题与标准答案 → 规则引擎示范 → LoRA SFT → 确定性评分器评测，在 0.6B 上就能从 0% 到 48%，在 4B 上从 3.6% 到 79%–85%，三个随机种子一致，训练每次 17 分钟、$0.15。
2. **先修 Harness，再训练，顺序是对的。** Harness v1 → v2 把失败从"全是工具交互问题"变成"主要是判断问题"（归因首错 73:0 → 22:47，P2S 33:21 → 5:45）；v2.1 又修掉三处交互缺口（维度名当指标名、market=ALL、回合用完不提交）。修 Harness 的成本是几行代码，训练的成本是 GPU 小时，所以能用 Harness 修的先修。
3. **没训练的模型不是"题太难"，是不会这套打法。** 4B 未训练时平均分 0.72（先查流量、不编号、格式都会），但 10 类主因里 7 类一次都没答对，把"没有异常"系统性地答成"模型漂移"；这些是治理分类法里的概念，预训练语料里没有，示范数据一教就会。
4. **示范数据的"想法"必须由证据生成。** 0.6B 第一轮 SFT 的教师强制诊断显示 token 一致率 99.8% 但分支点就错：模板式想法让模型按位置记步骤。改成"S-102 占增量 100%，且同期有模型升级 → 查漂移"这种证据式想法后，新问法不再掉分（0.6B 时 61% 对 31%，4B 时 85% 对 85%）。
5. **GRPO 在归因上没有可靠提升，在 P2S 上有一致的小幅提升。** v1（随机抽题、每轮一步）83.5% → 81.4%，在噪声内；v2（按通过率挑题、PPO 裁剪 + KL、探针早停、学习率 5e-6）三个 RL 种子在补数据 SFT 之上归因 +4 / +1 / 0 题（平均不到 1 个点，种子间不一致），P2S +3 / +7 / +17 题（平均 6 个点，三个种子同向，涨在分数线达标上）（第 11、14 节）。学习率 2e-5 的那次三轮就把起点打坏，RL 对步长极其敏感。同一笔钱花在修示范上（结论 6、9）提升是 RL 的几倍，RL 应放在最后一步。
6. **补稀有类示范把短板直接补上。** 只加数据不改模型：召回下降类 0/11 → 11/11，归因 85% → 94%（两个种子 92%–94%），P2S 63% → 69%（第 13 节）。先看错在哪一类、补那一类的示范，比上 RL 便宜得多也有效得多。
7. **数据质量比模型大小更值钱（在这个量级上）。** 补数据后 8B 只比 4B 多对 4 题（96.4% 对 94.3%，第 15 节），优势集中在升级判断； 同一个 0.6B 模型，示范数据从 v1（模板想法）换成 v2（证据想法）并配上 Harness v2.1，同一套 73 题从 48% 到 75%（+27 个点）；同样的 v2 数据从 0.6B 换到 4B，再从 75% 到 85%（+10 个点）。先把数据和 harness 做对，再谈换大模型。
8. **短板清楚且一致**：召回下降（规避）类 0–3/11，"误判率上升"问法下的模型漂移 31%，P2S 同时满足三个约束的收紧题 7–17/54。前两类示范数据少（9 条 / 15 条），先补数据比先做 RL 便宜。
9. **示范里的"想法"要写出选择规则，不只是答案。** P2S 的教师想法从模板改成"列约束 → 列满足约束的候选线 → 取覆盖率最高且留余量的"，一条归因示范没动，P2S 从 69% 到 89%–97%，收紧类分数线达标率到 97%–100%（第 16 节）。归因看起来变得不稳（170–191），但只训归因的对照也是 177 / 181：这是 1 epoch SFT 本身在"误判率上升"这一类（16 题）上的波动，不是 P2S 示范的干扰。**混合数据训 2 个 epoch 两边都保住**：两个种子归因 182 / 186、P2S 147 / 136，成为当前可用版本。归因上单次运行小于 10 题的差异不能当结论，门槛按多种子中位数定。

### 可信度边界

题目、答案、示范都来自同一个规则引擎，分数衡量的是"与规则引擎一致的程度"，不是现实准确率；测试世界与训练世界来自同一个生成器；主要数字是贪心解码（pass@k 只在第 13 节做了一次）。外部验证需要一批人工标注的真实题，这是上线前由使用方完成的门槛，原型阶段没有标注者，本报告不含任何真实数据上的结果。详细讨论见第 7 节。

**73 道失败题里，第一个错误全部属于 Harness 可修的一类。** 模型在走到“需要判断”的那一步之前，就先在参数、步骤、格式上出错了，所以这一轮基线还看不出它的判断力差多少。

两个 Harness 自身的问题值得单独指出：
- 148 次格式错误中，115 次是模型写出了完整 JSON、只漏了结尾标签，其余 33 次是工具名不存在。前者完全是解析器过严造成的，至少有一题因此丢掉了一个正确答案。
- 162 次 score_drift 报错是同一个原因（起止日期写反），报错信息没有给出正确示例，导致 12 题陷入循环。

| 改错了策略或市场范围 | 11 | 赌博人审题改了下播策略 S-115 并限定到 US | 训练 |
| 决策类型错 | 10 | “只改措辞”的题却去改了 S-102 | 训练 |

工具层面的问题同样集中在 harness 可修的一类：61 次 get_strategy_config 报 not_found（把动作名或 policy 编号当策略编号过滤），22 次 backtest_rule 参数错（分数线列表写成对象），分数线常被写成 28、90 这类百分数或人审容量。门控退回 84 次（编号 37、没回放 47），但每类最多退回两次，之后仍接受了提交。

**P2S 的 Harness 第 2 版要做的事**：get_strategy_config 接受“动作”过滤并忽略不合法的编号；backtest_rule 容忍对象形式的分数线列表；分数线大于 1 时按百分数换算或退回并提示；提交时 strategy_id 必须是工具返回过的 S-xxx 或 NEW。修完后重跑基线，剩下的“改错策略 / 决策类型错 / 分数线选不准”才是训练目标。

### 5.1 Harness v2 上的基线

同一个 Qwen3-0.6B、同一个评分器，只换成 P2S Harness v2（`--harness v2`）：

| 指标 | P2S v1 | P2S v2 |
|---|---|---|
| 全对 | 2 / 56 | 6 / 56（全部是“只改措辞”题） |
| 决策类型正确 | 39% | 64% |
| 不编造编号 | 41% | 91% |
| 提交前成功回放 | 0% | 47% |
| 分数线达标 | 9% | 36% |
| 改对策略 | 0% | 9% |
| 失败首错：harness / 训练 | 33 / 21 | 5 / 45 |

和归因任务一样：修好 harness 之后，失败几乎全部变成判断问题（改错策略 26、决策类型错 15、动作错 4）。收紧、市场专项、处罚调整三类题仍然一题没过。

## 6. 训练与训练后结果（方案 A：Qwen3-0.6B LoRA SFT，Harness v1）

**训练**：189 条规则引擎示范轨迹（16 个训练世界），LoRA r=16，2 个 epoch，95 步，只在助手自己生成的 token 上算 loss。CPU 上约 5.3 小时（中途容器重启多次，靠每步存档续跑）。loss：第 1 步 0.94 → 第 10 步 0.34 → 第 25 步 0.10 → 第 50 步 0.06 → 第 95 步 0.003，后半程基本在背示范轨迹。

**测试集（6 个没见过的世界，73 题）**：

| 指标 | 训练前 v1 | 训练前 v2 | **SFT（v1）** | 规则引擎 |
|---|---|---|---|---|
| 全对率 | 0% | 5.5% | **47.9%** | 100% |
| 平均得分 | 0.48 | 0.67 | **0.83** | 1.00 |
| 主因正确 | 6.8% | 9.6% | **51%** | 100% |
| 升级判断正确 | 58% | 51% | **81%** | 100% |
| 先查流量 | 0% | 82% | **100%** | 100% |
| 无编造编号 | 27% | 80% | **93%** | 100% |
| 有格式错误的回合 | 40% | 11% | **1.4%** | 0% |
| 平均工具调用 | 3.3 | 3.1 | 4.3 | 5.2 |

**按问法**：训练时见过的 A 类问法 61%，没见过的 B 类问法 31%。换个说法就掉一半，说明学到了不少问法模板。

**按主因**（测试集刻意放了训练中没出现过的组合）：

| 主因 | 题数 | 通过 | 说明 |
|---|---|---|---|
| 公会健康分（真实违规） | 6 | 100% | |
| 样本不足（小市场） | 6 | 100% | |
| 正常波动 | 18 | 78% | |
| 需要澄清 | 6 | 67% | |
| 新策略上线 | 6 | 33% | |

| 模型漂移 | 12 | 8% | 测试世界的漂移场景（暴力、未成年）训练中从未出现 |
| policy 更新 | 6 | 0% | |
| 公会集中 | 6 | 0% | |

**失败归类（SFT 后）**：38 道失败题里，29 道是“格式和步骤都对，但选错主因”，只有 9 道是 harness 能管的问题。SFT 基本解决了“会不会用工具”，没解决“换个场景还能不能判断对”。

**结论**
1. 链路是通的：示范轨迹 → SFT → 确定性评分，在 0.6B 模型上就能从 0% 提到 48%。
2. 提升主要来自行为层面（先查流量、不编号、格式正确），判断层面的泛化很弱：没见过的漂移场景只有 8%，新问法掉一半。这正是方案 B 要解决的，需要更大的模型、更多样的示范（多问法、多场景），以及在“有时对有时错”的题上做 RL。
3. loss 降到 0.003 说明在背轨迹。方案 B 应减少 epoch、加大数据多样性，并用留出的世界做早停。
4. 这一轮 SFT 用的是 Harness v1 的数据。按约定的顺序，下一轮训练用 Harness v2 的格式重新生成示范数据（同时修掉两处示范瑕疵），先在 v2 上重跑基线，再训练。

**训练集 20 题抽查**：在训练过的题上只答对 11/20（55%，平均得分 0.81），和测试集（48%）差不多，而训练 loss 已经降到 0.003。

**Teacher-forcing 诊断**（`posttrain/teacher_forcing.py`，把训练时的 token 序列原样喂给训练后的模型，看每个助手 token 的贪心预测是否等于示范）：
- 20 条示范轨迹、11,000 多个助手 token，逐 token 一致率 99.8%；11/20 条完全复现，与自由运行时答对的 11/20 正好对上。
- 所以**不是训练与推理不一致**：格式、工具参数、观察拼接全部能复现。
- 9 条有偏差的轨迹，第一个偏差几乎都在某一轮助手回合的**第一个词**上，也就是“下一步做什么”的决策点：示范写“按策略下钻”，模型写“证据充分，提交”或“查同期变更”；示范写“检查模型分漂移”，模型写“抽样 case”。一个 token 选错，后面的观察就是它没见过的分支，整条轨迹跑偏。
- 根本原因在示范数据：每一步的“想法”是按工具名套的固定模板（“按策略下钻。”），**没有引用上一步的观察**。模型只能靠位置记住“第几步该做什么”，无法学到“看到命中集中在一条策略，所以去查变更”这种条件关系。loss 很低是因为模板词占了绝大多数 token，真正承载决策的那几个 token 被平均掉了。

**对下一轮训练的直接含义**：
1. 示范里的想法要由观察生成（例如“S-102 占增量 100%，且同期有模型升级 C-006 → 检查分数漂移”），让决策 token 有可依赖的证据；
2. 训练时给每个助手回合的前几个 token 更高的权重，或单独统计“决策 token 准确率”作为早停指标；
3. RL 的奖励正好落在这些分支点上，这也是方案 B 里 GRPO 的用武之地。

## 7. 这些结论有多可信

**可以比较放心的结论**
- 同一个现象在两类任务上都出现了：修好 harness 后，失败从 harness 类转为判断类。归因任务的失败首错从 73 : 0（harness : 训练）变为 22 : 47，Policy-to-Strategy 从 33 : 21 变为 5 : 45。这支持“先做 harness，再决定训练什么”的顺序。
- SFT 后的提升明显大于随机波动：测试集 35/73，95% 区间约 37%–59%；训练前 Harness v2 为 4/73，区间约 2%–13%，两个区间不重叠。

**还不能当成科学结论的地方**
1. 只跑了一次：单一随机种子、贪心解码，没有重复实验，也没有多次采样（pass@k）。
2. 样本小且不独立：测试集只有 6 个世界；同一道题的 A/B 两种问法算两题，彼此相关。按问法、按主因拆开后，每格只有 3–18 题，区间很宽（例如 B 类问法 10/32，区间约 18%–49%）。
3. 对照不完全对齐：SFT 在 Harness v1 上训练和评测，而更公平的训练前基线在 v2 上。需要在同一版 harness 上比较训练前后。
4. 存在循环：题目、标准答案和示范轨迹都来自同一个规则引擎，题目也只保留规则引擎能做对的。分数衡量的是“和规则引擎一致的程度”，不是现实中的正确率。
5. 测量本身可能有偏差：训练集抽查只有 55%，可能存在训练与推理不一致，会把 SFT 的分数压低。
6. 只测了一个 0.6B 模型：结论能否推广到更大的模型，还不知道。

**要变成可信的实验结论，至少还需要**：3 个以上随机种子或温度采样并报告区间；在同一版 harness 上做“只改 harness / 只训练 / 两者都做”的消融；更大、更独立的测试集，加上一类训练中完全没出现的任务；一个不训练的大模型基线；先排查训练与推理是否一致；如果可能，再用一小批人工标注、贴近真实的题做外部验证。

## 8. 下一步

1. Harness v2 已完成（归因与 P2S 各一版）。下一轮训练用 v2 格式重新生成示范数据，并修正示范数据的两处已知瑕疵（冻结金额一步的说明文字写成“按策略下钻”；提交时漏掉次要原因和资金侧影响）；每条结果记录 harness 版本号；评分器只追加检查、不改已有规则。
2. 先排查训练集抽查 55% 的原因（teacher-forcing 诊断，`posttrain/teacher_forcing.py`），再做同版 harness 的训练前后对比与多种子重复；之后剩下“需要训练”的失败交给方案 B（更大模型，SFT + GRPO）。

## 9. 更大的模型不训练直接做：Qwen3-4B / 8B 基线（GPU，Harness v2）

跑在 Runpod 一张 A40 上（vLLM，贪心解码），代码 commit 见 `posttrain/runs/gpu/4wax5202lg6e1a/results/commit.txt`。测试集扩大为 16 个测试世界：归因 194 题，Policy-to-Strategy 150 题。两个模型都没有任何训练，只换了 Harness v2 的系统提示。

| 模型 | 归因通过 | 归因平均分 | 主因正确 | 没提交 | P2S 通过 |
|---|---|---|---|---|---|
| Qwen3-4B | 7/194（3.6%） | 0.724 | 10.9% | 28 | 24/150（16%） |
| Qwen3-8B | 7/194（3.6%） | 0.656 | 13.0% | 59 | 61/150（41%） |
| 参考：Qwen3-0.6B SFT 后（Harness v1，73 题） | 35/73（48%） | 0.833 | — | — | — |

（0.6B 的数字在旧的 73 题、Harness v1 上，不能直接比，放在这里只为给数量级。）

**题目是不是太难了？不是，是没训练的模型不会这套“打法”。** 证据：

1. **通过标准是 8 项全对**，而 4B 的平均得分有 0.72：先查流量（94%）、不编造编号（93% 的公会编号对）、格式（只有 1 题解析失败）这些都已经会了，错的集中在一项：**选主因**（10.9% 对）。
2. **错法是系统性的，不是随机的。** 4B 把“模型漂移”当锤子：48 道“没有异常”的题，29 道答成模型漂移、11 道答成流量；10 类主因里，有 7 类它一次都没答对过（策略变更、新策略上线、公会集中、公会真实违规、数据不足、需要澄清、召回下降）。这些是我们这套治理分类法里的概念，预训练语料里没有，模型自然答不出来；但它们在 0.6B 的 SFT 里就学会了一部分。
3. **一部分失败是和工具的交互问题，不是判断问题。** 4B 有 25 题、8B 有 56 题是 14 次调用用完还没提交：把维度名当指标名（`metric="strategy_id"`）反复报错，或者在 P2S 里给回测工具传 `market="ALL"` 被拒（4B 49 次、8B 54 次）。这两处已在 Harness v2.1 里修掉（维度名自动改成 group_by；ALL 表示不限市场），并新增“剩 2 次调用时提醒提交”。这类修完后预计两模型各能再多提交 10%–30% 的题，但主因对错不会因此改变。
4. **规则引擎本身在这些题上是 100%**（题目生成时就只保留规则引擎能做对的），说明证据是够的，答案是可达的。

**8B 比 4B 好在哪、差在哪。** 8B 在 P2S 上明显更强（41% 对 16%；32 道“只改措辞、不改策略”的题全对，4B 只对 14 道），说明读懂 policy 文本、判断“要不要动”的能力随规模上升。但 8B 在归因上更爱继续查、更不愿意下结论（没提交 59 题；平均调用 10.4 次 对 7.0 次），也更常答错升级判断。两者的主因准确率都在 11%–13%，差别在噪声范围内。

**对后续训练的含义。** 4B 已经把“查什么”学得差不多，缺的是“看到证据后选哪个主因”，这正好是示范数据（v2，想法由证据生成）和 GRPO 奖励要补的东西；而且它便宜一半、快一倍。所以 B1（LoRA SFT × 3 个种子）先在 4B 上做，8B 作为对照留到 B1 结果出来后再决定。

**这次运行的费用和一个教训。** Pod 跑了 2 小时 07 分（约 $1.25），其中任务本身 23 分钟，其余是跑完后一直等着：我的会话在那段时间被用量限制卡住，没人去下载结果和关机，定时的费用兜底检查也发不出去。之前一个 Pod 还因为控制脚本在结果没下载好时就终止，丢过一次 4B 的结果（约 $0.15）。两点改进：控制脚本只在结果核对完整后才终止；Pod 脚本支持通过 Runpod 账户密钥让 Pod 在 DONE 后 45 分钟自己删除自己（需要在 Runpod 控制台建一个存 API key 的 secret，key 不经过这边）。累计 GPU 花费约 $2。

## 10. 方案 B 第一步：Qwen3-4B LoRA SFT × 3 个种子（GPU，Harness v2.1）

同一张 A40，同一份代码，同一个 Pod 里先后跑：不训练的 4B 基线、三个随机种子各训练一次（LoRA r=16，1 个 epoch，113 步，每个约 17 分钟，训练数据 = 归因 v2 示范 374 条 + Policy-to-Strategy 示范），然后四个模型在同一套测试题上评测（归因 194 题、P2S 150 题，Harness v2.1，贪心解码）。结果目录 `posttrain/runs/gpu/950tkfermb1zb0/results/`。

| 模型 | 归因通过 | 95% 区间 | 平均分 | 主因正确 | P2S 通过 |
|---|---|---|---|---|---|
| 4B 不训练 | 6/192（3.1%） | 1%–7% | 0.779 | 10.4% | 31/150（21%） |
| 4B SFT 种子 1 | 165/194（85.1%） | 79%–89% | 0.953 | 87.1% | 95/150（63%） |
| 4B SFT 种子 2 | 153/194（78.9%） | 73%–84% | 0.931 | 81.4% | 79/150（53%） |
| 4B SFT 种子 3 | 154/194（79.4%） | 73%–84% | 0.940 | 83.0% | 85/150（57%） |

**可以放心说的**
1. 训练前后的差距远大于种子间的差距：三个种子都在 79%–85%，区间和基线（1%–7%）完全不重叠。这次是同一版 harness、同一套题、三个种子，第 7 节里说的"对照不对齐、只跑一次"两个问题都补上了。
2. 新问法不再掉分：A/B 两种问法分别 85%/85%、78%/80%、80%/79%，而 0.6B 那轮是 61% 对 31%。v2 示范数据里"想法由证据生成"看来起了作用，模型学到的是条件关系，不是位置。
3. 基线一次都没答对的 7 类主因，训练后大多数接近全对：没有异常 48/48、公会真实违规 16/16、需要澄清 16/16、新策略上线 16/16、策略变更 15/16、数据不足 15/16、公会集中 14/14（种子 1）。
4. P2S 上"该不该改、改哪条"学会了（决策、目标策略、资金审批标记都 100%），"只改措辞"和"换动作"两类 32/32 全对。

**还没学会的（三个种子一致）**
- **召回下降（规避）**：11 题只对 0–1 题，三个种子都答成"没有异常"。看轨迹，模型查了命中数就下结论，没有去查召回估计（`recall_est`），而示范里这一类只有 9 条（占 5%）。这是 RL 最该发力的地方：奖励会直接惩罚"没查召回就说正常"。
- **误判率上升这种问法下的模型漂移**（overturn_up 类）：只对 6%–31%，常答成"数据不足"或"没有异常"，也就是没去做分数漂移检查。
- **P2S 的分数线**：要同时满足覆盖率、精确率、人审量上限的"收紧"题只对 4–17/54，分数线在评分窗口达标率约 50%。回放窗口和评分窗口的分布差异让这类题本身就有不确定性，示范也只给了一个"最保守可行解"。

**一个配置问题。** 三个 SFT 模型分别有 19%、14%、27% 的题出现过"提交卡片被截断"：想法写得长，加上 JSON 卡片超过了每轮 220 个 token 的上限，被判格式错误后重试一次才交上。基线模型想法短，从没碰到。这不是模型问题，v2.1 把上限改为 384；36 个被截断的题里 33 个最终还是通过了，所以对上面的数字影响很小。

**对下一步的含义**
1. 4B + SFT 已经进入"有时对有时错"的区间（召回类 0–9%，overturn_up 类 6%–31%，P2S 收紧类 7%–31%），这正是 GRPO 能起作用的区间：奖励来自确定性评分器，不需要人标注。
2. 如果只做一轮 SFT 就上线原型，种子 1 这版（85% / 63%）已经比 0.6B 那版（48%）可用得多，但召回类几乎全错，必须在产品里把"召回下降"类问题标成"助手暂不擅长"，或者先补示范数据。
3. 费用：这一 Pod 1 小时 30 分，约 $0.90。累计 GPU 约 $3。

**可信度提醒**：测试世界和训练世界来自同一个生成器，分数仍然是"和规则引擎一致的程度"；三个种子只是训练随机性，不是数据随机性（题目没换）；贪心解码，没有 pass@k。

## 11. 方案 B 第二步：在 SFT 之上做 GRPO（GPU，Harness v2.1）

设置：从第 10 节的 4B SFT 种子 1 出发，在训练世界的 266 道题（归因 189 + Policy-to-Strategy 77）上做 GRPO。每轮随机抽 48 题，每题用 vLLM 以温度 1 采样 8 条完整轨迹（共 384 条），奖励 = 评分器得分（0–1）+ 通过加 1；同一题 8 条轨迹内归一化得到优势，8 条结果完全一样的题不产生梯度（相当于只练"有时对有时错"的题）；每轮对有信号的轨迹做一步策略梯度（只更新 LoRA，学习率 1e-5，梯度裁剪 1.0），再把新 LoRA 热换进 vLLM。预算 2 小时，实际跑了 9 轮（每轮约 15 分钟：采样 6–9 分钟 + 训练 7–9 分钟）。评测用同一 Pod、同一 384 token 上限，和 SFT 直接可比。结果目录 `posttrain/runs/gpu/jap7pjgtdamy4i/results/`，实现 `posttrain/grpo.py`。

| 模型 | 归因通过 | 95% 区间 | 平均分 | 主因正确 | P2S 通过 |
|---|---|---|---|---|---|
| 4B SFT 种子 1（同 Pod 重测） | 162/194（83.5%） | 78%–88% | 0.948 | 87.1% | 85/150（57%） |
| 4B SFT + GRPO 9 轮 | 158/194（81.4%） | 75%–86% | 0.952 | 87.1% | 89/150（59%） |

**结论：这 2 个 GPU 小时的 GRPO 没有带来可测量的提升。** 逐题配对看，归因 194 题里 153 题两者都对、27 题都错、SFT 独对 9 题、GRPO 独对 5 题，差异在噪声范围内；P2S 多对 4 题，同样在噪声内。训练过程中每轮采样的通过率在 65%–79% 之间上下跳（73 → 74 → 77 → 66 → 79 → 65 → 71 → 74 → 74%），没有上升趋势；loss 本身接近 0（这是 GRPO 的正常现象，不能当收敛指标）。

按类别拆开看，变化也都在一两题之内：召回下降类 1/11 → 3/11（GRPO 后开始有答对的，但也把 2 题答成"公会集中"）；误判率上升问法下的模型漂移 31% → 31%；P2S 收紧类 17/54 → 15/54，换动作类 29/32 → 32/32，新市场规则类 7/32 → 10/32。

**为什么没涨（诊断，供下一轮改）**
1. **更新量太小。** 每轮只做一步梯度、学习率 1e-5、有效样本约 170–250 条轨迹，9 轮合计不到 2,000 条；SFT 阶段是 374 条示范 × 多个 token 的监督信号。要让 RL 起作用，通常需要几十到上百轮，或每批多步更新（加 PPO 式的比率裁剪和对参考模型的 KL 约束）。
2. **练的题不对。** 随机抽题，而训练集里大多数题 SFT 后已经 8/8 全对（每轮只有 21–31 组有信号），真正该练的召回类只有 9 道训练题，9 轮里平均只被抽到 1.6 次。应该按"上一轮通过率在 20%–60%"主动挑题，并对稀有类别过采样。
3. **采样与评测的差距。** 训练时温度 1 采样，评测时贪心解码；温度 1 下的奖励波动（每轮 ±7 个点）大部分来自抽题不同和采样随机性，不是模型变化，所以单轮奖励不能用来判断好坏。应固定一小批"探针题"每轮用贪心跑一次作为早停信号。
4. **显存与实现细节。** 一次性算整段序列的 logits 在 A40 上触发了显存分配重试（没中断），已改成分块计算；训练与推理共享一张卡，vLLM 只能用 45% 显存，采样慢。

**这一轮的含义。** 对产品原型而言，SFT 版（83.5% / 57%）就是目前可用的最好版本，GRPO 版没有理由替换它。对方法而言，这次验证了"vLLM 采样 → 评分器奖励 → 策略梯度 → 热换 LoRA"的回路在真实 GPU 上能跑通（9 轮无故障，每轮 15 分钟，$0.15/轮），但要出效果需要上面四点改动，预计再花 $5–10、4–6 小时 GPU。是否继续，看项目优先级：召回类和 P2S 收紧类的短板也可以先用补示范数据（成本更低）的方式试一次。

**费用。** 本 Pod 2 小时 55 分，约 $1.75；第一次 B2 因导入路径错误白跑 25 分钟（$0.25）。GPU 累计约 $5.5。

## 13. 补稀有类示范数据后的 SFT：短板补上了

第 10 节三个种子一致的短板是召回下降类（0–1/11）和"误判率上升"问法下的模型漂移（6%–31%）。这一轮只改数据，不改模型和 harness：追加 16 个训练世界（w32–w47，测试世界不变，脚本校验测试题 md5 未变），并对这两类任务做过采样（每道题最多再加 6 / 2 条不同日期、不同措辞的示范）。示范从 374 条增加到 831 条（召回类 9 → 65 条，误判率上升问法 15 → 116 条），其余类别也随新世界翻倍。训练仍是 LoRA r=16、1 个 epoch（227 步，4B 约 45 分钟）。评测同口径：Harness v2.1、194 + 150 题、384 token 上限、贪心。结果目录 `posttrain/runs/gpu/88wl9yil4y9k6b/results/`。

| 模型 | 示范 | 归因通过 | 95% 区间 | 主因正确 | 召回下降类 | 误判率上升问法 | P2S 通过 |
|---|---|---|---|---|---|---|---|
| 4B SFT 种子 1（第 10 节） | 374 条 | 165/194（85.1%） | 79%–89% | 87.1% | 0/11 | 31% | 95/150（63%） |
| 4B SFT 种子 1（补数据） | 831 条 | 183/194（94.3%） | 90%–97% | 96.4% | 11/11 | 44% | 103/150（69%） |
| 4B SFT 种子 2（补数据） | 831 条 | 179/194（92.3%） | 88%–95% | 97.4% | 11/11 | 56% | 103/150（69%） |

**读法**
- 两个种子都到 92%–94%，区间与第 10 节的 79%–85% 不重叠。逐题配对（种子 1 对种子 1）：164 题两版都对，19 题只有新版对，1 题只有旧版对，10 题都错。
- **召回下降类从 0/11 到 11/11**：示范里多了"命中少了但举报没少、召回估计在掉"的轨迹后，模型学会了去查召回估计再下结论。10 类主因里现在 8 类全对或只错 1 题。
- **"误判率上升"问法从 31% 到 44%–56%**，仍是最弱的一类。剩下的错法已经变了：不再是"没去查漂移"，而是查到之后把主因写成"策略变更"（3 题，变更编号也跟着错）或者升级判断错（该升级没升级，4–5 题）；种子 2 还有 5 题在结论里带了一个本轮没见过的编号被判幻觉。这些是示范里对这类题的"升级"和"编号引用"写法还不够一致，不是数据量问题。
- **P2S 从 63% 到 69%**：换动作类和改措辞类 32/32 全对，决策和目标策略接近全对（98.7% / 98.3%）；剩下 45 道失败全是"分数线在评分窗口不达标"（收紧题 21/54，新市场规则 18/32），这是回放窗口与评分窗口分布差异造成的，示范只给一个最保守解，模型学不到"留余量"。下一步改示范让它给带余量的分数线，或者在评分器里把容差按回放噪声标定。
- **新问法不掉分**：A/B 两种问法 93% 对 96%。

**pass@k（温度 0.7，每题 4 次采样，种子 1）**：pass@1 90.3%，pass@4 97.4%，4 次全对 80.4%，4 次结论一致 83%。温度采样下的单次通过率比贪心低 4 个点，说明贪心数字略偏乐观；pass@4 接近 97% 说明大多数错题是"有时会对"的题，正是 RL 能啃的区间（但第 14 节会说明这一版 RL 没啃动）。

**8B 这次没跑成**：8B 的训练写日志时碰到网络卷的 I/O 错误（`OSError: [Errno 5]`），和 GRPO 第一次重跑挂掉的原因相同；已把模型缓存、LoRA 和 RL 状态改到容器本地盘，8B 对照单独补跑（第 15 节）。

**对产品的含义**：4B + 831 条示范的版本（94% / 69%）取代第 10 节的版本成为当时可用的最好版本；它的两个剩余短板（误判率问法下的升级判断、P2S 分数线余量）都有明确的数据侧修法，第 16 节把后者修掉了。

## 14. GRPO 第二版：针对第 11 节诊断的改版

起点是第 13 节的补数据 4B SFT（同 Pod 内重新训练的种子 1）。改了四处（`posttrain/grpo2.py`）：按每题的通过率估计挑题（估计在 20%–60% 的题权重 3，全对或全错的 0.3，稀有类再乘 2）；每批做多步 PPO 裁剪更新并对 SFT 参考模型加 KL 约束；每轮用 48 道固定题（一半稀有类）贪心跑一遍作探针，最终版取探针最高的一轮，SFT 起点本身也是候选；训练和采样同一张卡但状态写容器本地盘。

**第一次运行（学习率 2e-5，每批 2 轮）失败**：探针 0.896 → 0.812 → 0.833 → 0.75，三轮连降，提前终止（$0.9）。更新量仍然太大。

**第二次运行（学习率 5e-6，每批 1 轮，10 轮，2.5 小时 RL）**，探针曲线：起点 0.854 → 0.875, 0.875, 0.938, 0.938, 0.896, 0.875, 0.875, 0.875, 0.917, **0.958**, 0.938。取第 9 轮为最终版。结果目录 `posttrain/runs/gpu/kzyrnjf3rw9eam/results/`。

| 模型（同 Pod、同口径） | 归因通过 | 95% 区间 | 主因正确 | 升级判断 | 误判率上升问法 | P2S 通过 |
|---|---|---|---|---|---|---|
| 4B SFT 种子 1（起点） | 180/194（92.8%） | 88%–96% | 96.4% | 93.8% | 62% | 99/150（66%） |
| 4B SFT + GRPO v2 | 184/194（94.8%） | 91%–97% | 96.9% | 96.1% | 69% | 102/150（68%） |

**读法**
- 多对 4 题（逐题配对：176 题都对，GRPO 独对 8 题，SFT 独对 4 题，6 题都错），P2S 多对 3 题。方向是正的、探针曲线也在涨，但区间重叠，单次运行不能排除噪声；要下"RL 有效"的结论至少需要再跑两个种子。
- 涨的地方和奖励对得上：**升级判断** 93.8% → 96.1%（SFT 剩下的错题里一半是"主因对、升级错"，这正是评分器会惩罚的），"误判率上升"问法 62% → 69%。主因准确率几乎不变（96.4% → 96.9%）。
- 曲线为什么能涨而第 11 节不能：第 11 节每轮一步、学习率 1e-5、随机抽题，9 轮里有信号的组一直在减少；这一版把每轮的训练样本集中在"有时对有时错"的题上（每轮 10–17 组有信号），学习率降到 5e-6 后更新不再把起点打坏，探针早停保证最终版不会比起点差。
- 代价：每轮约 15 分钟（采样 5–7 分钟、训练 5–8 分钟、探针 2 分钟），10 轮 2.5 小时、$1.5；加上第一次失败的 $0.9，GRPO v2 合计 $2.4。
- **和"补数据"相比**：补数据一次 SFT 把 85% 提到 94%、成本 $0.5；RL 在此之上再提 2 个点、成本 $2.4，且需要多种子验证。顺序应当是"先补数据，再用 RL 磨剩下的判断类错误"。

**还能改**：探针每轮 2 分钟、48 题太少（一题 = 2 个点，曲线噪声大），应扩到 96 题或改为每两轮一次；"saturated"题数一路涨到 209/266 说明训练集快被学完，下一步要从新世界补题而不是继续在同一批题上采样。

### 14.1 多种子验证：归因上没有可靠提升，P2S 上有

同一配置（学习率 5e-6、每批 1 轮、10–12 轮、探针早停）再跑两个 RL 种子，各自从同 Pod 内重新训练的补数据 SFT 种子 1 出发（三个 Pod 的 SFT 起点是三次独立训练：180 / 180 / 183）。RL 的采样题包含归因题和 P2S 题。结果目录 `posttrain/runs/gpu/{kzyrnjf3rw9eam,22yndokyqwisbn,iljz4ipkab17qj}/results/`。

| RL 种子 | 探针起点 → 最高（第几轮） | 归因 SFT → GRPO | 逐题（都对 / 只 GRPO 对 / 只 SFT 对 / 都错） | 升级判断 | P2S SFT → GRPO | P2S 逐题 |
|---|---|---|---|---|---|---|
| 1 | 0.854 → 0.958（9） | 180 → 184（+4） | 176 / 8 / 4 / 6 | 93.8% → 96.1% | 99 → 102（+3） | 94 / 8 / 5 / 43 |
| 2 | 0.875 → 0.938（5） | 180 → 181（+1） | 178 / 3 / 2 / 11 | 95.5% → 96.1% | 118 → 125（+7） | 117 / 8 / 1 / 24 |
| 3 | 0.896 → 0.958（11） | 183 → 183（0） | 178 / 5 / 5 / 6 | 96.6% → 97.2% | 104 → 121（+17） | 99 / 22 / 5 / 24 |

**读法**
- **归因：三个种子 +4 / +1 / 0，平均 +1.7 题（不到 1 个点）**，三个种子合计 GRPO 独对 16 题、SFT 独对 11 题，在噪声内。第 14 节单种子的"+4"不能算 RL 的功劳。唯一在三个种子上同向的是升级判断（93.8 → 96.1、95.5 → 96.1、96.6 → 97.2），和奖励对得上，但每个种子只是 2–5 题。
- **P2S：三个种子 +3 / +7 / +17，平均 +9 题（6 个点）**，方向一致、幅度不小，三个种子合计 GRPO 独对 38 题、SFT 独对 11 题。涨的全是"分数线在评分窗口达标"这一项：RL 的奖励直接按评分窗口打分，模型学到了比示范更保守的分数线。注意这三个起点用的还是旧 P2S 示范（77 条模板想法，起点 99–118）；改示范一次 SFT 就到 134–145（第 16 节），比 RL 便宜得多也多得多。两者是否叠加还没测。
- 探针曲线三个种子都在涨（最高 0.938–0.958），但探针只有 48 题，和 194 题测试集的相关性弱：种子 2 探针从 0.875 到 0.938，测试集只多 1 题。探针应扩到 96 题以上再用来选最终版。
- 成本：每个种子 2.5 小时 RL + 评测，约 $2.1；三个种子合计约 $6.5。

**结论改为**：GRPO v2 在归因上没有可靠提升（平均不到 1 个点、种子间不一致），在 P2S 上有一致的小幅提升（约 6 个点）；但同一笔钱用在修示范上（第 13、16 节）带来的提升是 RL 的几倍。RL 的位置应当是最后一步：数据和 harness 都做对之后，用来磨评分器能直接打分、示范又写不清楚的那类判断（分数线余量、升级阈值）。

- P2S 两者几乎一样（70% 对 69%），失败都在"分数线在评分窗口不达标"，与模型大小无关，是示范和评分器口径的问题（第 13 节）。
- 8B 不训练时比 4B 不训练强（7.7% 对 5.2%，P2S 46% 对 21%），但训练后差距缩到 2 个点：数据把模型大小的差异抹平了大半。

**选型建议**：产品原型用 4B 即可（成本和延迟约为 8B 的一半，归因 94% 对 96%）；如果"误判率上升"这一类问法在真实场景里占比高、而且升级判断的代价大，再考虑 8B。

**费用**：本 Pod 1 小时 12 分，约 $0.7。

## 16. 修 P2S 示范的"想法"：分数线余量问题补上了

第 13 节剩下的 45 道 P2S 失败全是"分数线在评分窗口不达标"。原因在示范：教师（规则引擎）的"想法"是固定模板，提交时只给一个最保守的分数线，模型学不到"为什么选这条线"。这一轮只改示范的文字（`posttrain/p2s.py`）：回放前写出 policy 的约束（覆盖率 ≥ x、精确率 ≥ y、日均人审 ≤ z），回放后列出满足约束的候选线及其数字，并说明"取覆盖率最高、且留 2% 余量的那条"；提交的理由也带上这条规则。同时 P2S 示范改为从全部 32 个训练世界生成（77 → 153 条）。归因示范、模型、harness、评分器、测试集都没动（测试集 md5 和内容指纹校验未变，见 `eval/fingerprint.py`）。训练仍是 LoRA r=16、1 个 epoch（归因 + P2S 示范混合，246 步，36 分钟）。结果目录 `posttrain/runs/gpu/30ap848075ef6s/results/`。

## 17. 外部模型基线：前沿 API 模型零样本 / 少样本 对 训练后的小模型

前面所有数字都是开源小模型（0.6B / 4B / 8B）在本地 GPU 上的结果。这一节把同一套 194 道归因题、同一个 Harness v2.1、同一个评分器拿给前沿 API 模型做，不训练，回答两个问题：训练后的 4B 到底比"直接用大模型"差多少或强多少；评分器里"与规则引擎一致"的标准对一个没见过示范的强模型有多苛刻。

**做法。** 新增策略适配层 `posttrain/policy_api.py`：把 harness 的裸补全接口换成对话接口加结构化工具调用——harness 渲染的 system prompt、用户问题和工具列表原样交给 API，模型返回的 `tool_calls` 翻译回 harness 认的 `<tool_call>` 文本，工具结果、门控退回、格式错误再作为 tool_result 送回去。harness 的参数归一化、提交门控（先查流量、编号必须出现过、主因枚举）和评分器一行没改（`posttrain/harness.py`、测试集、评分器均未改动，`make check` 指纹不变）。Anthropic 一侧用官方 SDK，开提示缓存，全量跑可走 Message Batches（五折）；OpenRouter 一侧用 OpenAI 兼容接口，贪心解码。每组先跑 10 题核对格式与幻觉校验，再跑全量；费用按每题 usage 累计，记录在 `reports/external/<name>/`（summary、逐题紧凑结果、日志）。跑法在 `posttrain/run_api_baselines.sh`。

**读法。** 前沿模型零样本 79%、少样本 81%，对训练后的 4B 的 94%–96% 差 13–17 个点；但主因准确率 89%–90% 只差 4–7 个点，差距主要在两处约定：一是升级判断（每组 13 题取决于规则引擎抽不抽样、抽多少），二是"误判率上升"问法的累计口径和"公会健康分不需要日期"这两条提示里没写的流程。把抽样口径按证据判对后两组是 86%–88%。这和 17.1 的结论一致：前沿模型会用工具、会推理，缺的是这个平台的流程约定，而 4 条示范只能带进去示范里恰好有的那几条（公会集中要升级学会了，累计口径没学会），还会带进去不想要的细节（抽样 n=15、文本格式调用）。按同一口径比，4B 微调版本每题成本不到前沿模型的十分之一、单题 18 秒，还高 13–17 个点；前沿模型的价值在没有示范的新问题类型上（召回下降零样本 11/11），以及作为口径审计——它暴露出来的两处标准答案过窄（抽样决定升级、累计口径没写进提示）正是下一步要在评分器和提示里修的。
