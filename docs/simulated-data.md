# 模拟数据说明

这份文档写给不需要看代码的读者。原型用的全部是程序生成的合成数据：没有真实主播、真实直播或真实处罚，市场和数字也都是编的。数据的用途是搭一个"可以考试的世界"：我们事先在数据里埋好问题，知道标准答案，再看助手能不能找出来、会不会误报。

## 一分钟读懂

| 项目 | 取值 |
|---|---|
| 时间 | 2026-09-18 至 2026-10-15，共 28 天；"今天"设为 2026-10-16 |
| 市场 | 美国、巴西、印尼、英国（大市场，每天约 550–1,170 场直播）；越南、肯尼亚（小市场，每天约 20–60 场） |
| 直播场次 | 约 10.4 万场 |
| 风险类型 | 8 类：色情低俗、未成年人安全、诈骗引流、暴力血腥、垃圾刷量、赌博、仇恨骚扰、假冒侵权 |
| 策略 | 29 条（见 [模拟策略库说明](simulated-strategy-library.md)） |
| 公会 | 51 家，分布在 6 个市场；约 56% 的直播属于某个公会，头部主播几乎都有公会 |
| 埋入的问题 | 11 个，见下文 |
| 可复现 | 固定随机种子，任何人重新生成都得到完全相同的数据 |

## 数据是怎么"造"出来的

可以把它想象成一个按顺序运转的小平台：

1. **开播**：每个市场每天开播若干场，周末多一些。每场直播有主播层级（头部 2% / 腰部 18% / 尾部 80%）、账号年龄、观看峰值、打赏金额、时长、举报数、是否带外链、是否新设备、关键词命中数，以及所属公会。
2. **真相**：每场直播在后台抽一个"真实标签"，表示它到底有没有违规、属于哪一类。各类违规的基础比例在 1%–4% 之间，不同市场有高低（例如英国的骚扰比例更高）。这个真相只有出题人知道，助手看不到。
3. **模型打分**：8 个风险模型各给每场直播打一个 0–1 的分。真违规的通常分高，但也有约 12% 的正常直播是"难样本"，分数会偏高，这是误杀的来源。
4. **策略执行**：29 条策略按各自的阈值和条件去匹配，命中即执行动作；一场直播命中多条策略时，按最严重的动作处置。
5. **后续反馈**：被处罚的主播可能申诉；被误杀的更可能申诉，也更可能被推翻。观众会举报。质检团队会抽样复核，给出"到底违规没有"的判断。
6. **公会健康分**：每家公会每天根据旗下严重处置是否超出市场基准来扣分或回升。

助手只能像真实用户一样，通过查询工具看到第 1、3、4、5、6 步的结果。

## 指标口径

所有指标都有定义和版本号，助手回答时会写明用的是哪个口径。几个容易混的：

| 指标 | 定义 | 容易出错的地方 |
|---|---|---|
| 处罚率 | 处罚场次 ÷ 直播场次 | 流量暴涨时处罚数会涨，但处罚率可能不变 |
| 申诉推翻率 | 推翻数 ÷ 申诉数 | 和下一行分母不同 |
| 每处罚推翻率 | 推翻数 ÷ 处罚数 | 用户说"误杀率"时，可能指这个，也可能指上一行，助手要写明选了哪个 |
| 抽检精确率 | 抽检的命中样本里，确认违规的比例 | 小市场样本少，不可靠 |
| 召回估计 | 用抽检结果估算"该抓的抓到了多少" | 只能看趋势；小市场仅供参考 |
| 冻结金额 | 资金侧处置涉及的打赏合计 | 合成金额单位，不对应任何货币 |

模拟里被处罚的直播申诉后约七成被推翻，这个比例偏高。原因是我们刻意让误杀的主播更愿意申诉（约 70%），而真违规的主播很少申诉（约 12%）。这样设置是为了让"误杀上升"在数据里足够明显。

## 埋入的 11 个问题

这是"考卷"。每个问题都有标准答案，原型的评测集（37 道题）就是围绕它们出的。

| 编号 | 用户可能这么问 | 数据里发生了什么 | 正确结论 | 常见误判 |
|---|---|---|---|---|
| P1 模型漂移 | "美国最近误杀申诉涨了" | 10/13 诈骗模型升级，分数整体上移；S-102 阈值没动，误杀增加 | 模型漂移导致固定阈值失效，S-102 需重校；同模型的资金侧策略也受影响 | 以为是诈骗变多了 |
| P2 召回下降 | "巴西赌博处罚怎么少了" | 10/8 起违规者绕过模型，S-115 命中减半，举报不变 | 召回下降，不是违规减少 | 以为治理变好了 |
| P3 策略重叠 | 巡检 | S-104 与 S-121 命中完全重合 | 建议合并 | |
| P4 僵尸策略 | 巡检 | S-108 依赖已下线特征；S-119 条件太窄，均 0 命中 | 迁移或下线 | 把暂停的 S-127 也当成僵尸 |
| P5 流量陷阱 | "印尼 10/3 处罚暴涨" | 当天直播量从约 980 涨到约 1,730（+45%），处罚率不变 | 流量驱动，不是策略问题 | 以为策略出错 |
| P6 policy 更新 | "英国人审量翻了三倍" | 英国 policy 扩大骚扰定义，S-112 阈值同步下调 | 预期内变化 | 当成异常报警 |
| P7 新策略上线 | "印尼未成年处罚涨了" | 10/12 S-126 在印尼上线 | 新策略带来的预期增量 | 当成异常报警 |
| P8 头部主播误杀 | "还原一下 LS-0101617" | 10/15 一位头部主播被 S-102 断播，诈骗分 0.85，刚过阈值，处在模型漂移窗口 | 很可能是误杀，涉及头部主播，必须人工升级 | 直接给结论不升级 |
| P9 公会集中违规 | "巴西刷量处罚涨了" | 10/13–15 增量集中在一家公会 G-BR-002（新设备、新账号批量刷量） | 公会级问题，转公会治理 | 当成全市场问题 |
| P10 公会健康分 | "G-BR-002 健康分为什么掉了" | 三天从约 99.8 掉到 75，越过 80 分档位 | 旗下主播真实违规，按档位处置 | 当成策略误扣分 |
| P11 资金侧处置 | 归因或 case 还原 | 3 条资金侧策略 28 天冻结或延迟约 33.6 万 | 涉及资金时报出金额、提示解冻流程和财务知会 | 只说下播，漏了钱 |

另外还有 3 类"干扰项"，用来测试助手会不会过度归因：刷量模型 10/5 的热修复（分数不变）、未成年 policy 10/1 的措辞澄清（执行标准不变）、小市场的正常随机波动。

## 训练用的变体世界

为了后训练模型，原型可以按配置生成任意多个"平行世界"：结构相同，但问题埋在不同的地方（例如另一个市场的另一个模型漂移、另一家公会出事、另一个日期流量暴涨）。目前生成了 22 个：16 个用于训练，6 个用于测试。测试世界里的部分问题组合在训练中从未出现，用来检验模型是不是真学会了"怎么查"，而不是记住了"答案是 S-102"。

## 和真实数据的差异

合作方提问时可以直接说明这些简化：

- **规模小很多**：每天几千场直播，真实平台高出几个数量级。
- **一场直播只有一个真实标签**：现实中可能同时涉及多类问题，也可能界限模糊。
- **申诉当天裁决**：真实流程有排队和多级复核。
- **没有主播历史**：没有累犯、信用分、处罚升级链路。
- **公会健康分规则是假设的**：起始 100 分，严重处置超过市场基准 1.2 倍的部分每条扣 0.5 分，每天最多扣 10 分，没有超额则回升 0.5 分；档位为 80 约谈、70 暂停结算、60 扣当月收益、50 清退。真实规则请以业务为准。
- **金额是合成单位**：不对应任何货币或真实收入。

如果合作方指出"真实情况里还会遇到 X"，可以把 X 加成一个新的埋入问题，重新生成数据，再看助手能不能答对。这正是这套模拟数据的用途：把业务经验变成可以反复测试的题目。
