# 模拟策略库说明

这份文档写给不需要看代码的读者（策略、运营、公会治理、合作方）。原型里的 29 条治理策略全部是虚构的，编号、阈值、负责团队都不对应任何真实平台；它们的作用是搭一个"足够像"的策略库，让助手有东西可查、有问题可找。

## 一分钟读懂

- **29 条策略**：28 条在线，1 条已暂停（S-127）。
- **覆盖 8 类风险**：色情低俗、未成年人安全、诈骗引流、暴力血腥、垃圾刷量、赌博、仇恨骚扰、假冒侵权。
- **覆盖 6 个市场**：美国 US、巴西 BR、印尼 ID、英国 GB、越南 VN、肯尼亚 KE。其中越南、肯尼亚是故意设置的"小市场"，每天只有几十场直播，用来测试助手在样本不足时是否会保守。
- **由 7 个虚构的策略小组负责**：内容组、未成年组、交易安全组、生态组、平台生态组、社区组、电商治理组。
- **其中 5 条策略带了"病"**，另外几条有正常的、预期内的变化。助手要能区分这两种情况，见下文"策略在演示里扮演的角色"。

## 一条策略长什么样

每条策略都可以读成一句话：

> 在 **某些市场**，如果某场直播的 **某类风险模型分 ≥ 阈值**，并且满足 **附加条件**，就执行 **某个动作**。

例：S-114 诈骗-高打赏新号冻结收益

> 在所有市场，如果诈骗模型分 ≥ 0.60，且该场打赏 ≥ 500、主播账号注册不满 14 天，就冻结该场收益。

几个概念：

| 概念 | 白话解释 |
|---|---|
| 模型分 | 每类风险有一个模型，给每场直播打 0–1 的分，越高越像违规。原型里每场直播 8 类风险各有一个分 |
| 阈值 | 分数线。阈值越低，抓得越多，误杀也越多 |
| 附加条件 | 举报数、打赏金额、账号年龄、是否带外链、是否新设备、关键词命中数、观看人数等 |
| 动作 | 命中后做什么，从"只观察"到"封禁 7 天"共 9 级，见下表 |
| 版本 | 每次改阈值或动作都会升版本，留有生效日期，助手据此判断"某天之后为什么变了" |
| 状态 | active 在线 / paused 暂停。暂停的策略不会命中任何直播 |

## 处置动作梯度

一场直播同时命中多条策略时，按最严重的动作处置；资金侧动作可以和下播同时生效。

| 动作 | 中文 | 严重度 | 是否算处罚 | 资金侧 |
|---|---|---|---|---|
| observe | 观察 | 0 | 否 | |
| manual_review | 转人工审核 | 1 | 否 | |
| limit_traffic | 限流 | 2 | 是 | |
| warn | 警告 | 3 | 是 | |
| delay_settlement | 延迟结算 | 4 | 是 | 是 |
| freeze_earnings | 冻结违规场次收益 | 5 | 是 | 是 |
| suspend_live | 断播（下播） | 6 | 是 | |
| disable_gifts | 关闭礼物 | 7 | 是 | 是 |

原型的策略库里没有 disable_gifts 策略，这一级只在动作梯度里占位。

## 策略在演示里扮演的角色

### 带"病"的策略（助手应该发现）

| 策略 | 问题 | 数据里能看到什么 | 助手应该怎么说 |
|---|---|---|---|
| S-102 | 模型升级后阈值没重校 | 10/13 诈骗模型 v3 → v4（C-006），分数整体上移约 0.15；S-102 阈值固定 0.85，误杀和申诉推翻明显上升（10/6–12 七天推翻 48 次，10/13–15 三天推翻 158 次） | 模型漂移导致固定阈值失效，建议重校阈值；同模型的资金侧策略 S-114、S-129 也受影响，涉及冻结金额，误杀需解冻 |
| S-115 | 巴西赌博召回下降 | 10/8 起巴西赌博命中从每天约 16 次降到约 8 次，但举报量不变（每天约 40） | 不是违规变少，而是违规者在绕过模型（分数被压低），召回下降，需要补特征或补策略 |
| S-104 与 S-121 | 两条策略几乎重复 | S-104 命中的 2,240 场直播 100% 也被 S-121 命中；两条由不同团队维护 | 建议合并，保留一条，减少重复维护 |
| S-108 | "僵尸策略"：依赖的数据已下线 | 依赖的"旧品牌词表"特征 8/1 下线后恒为 0，策略再也不可能命中 | 迁移到新特征或下线 |
| S-119 | "僵尸策略"：条件太窄 | 要求观看峰值 ≥ 5 万且暴力分 ≥ 0.95，28 天 0 命中 | 评估是否放宽条件或归档 |

### 资金侧策略

S-114、S-129（冻结收益）和 S-125（延迟结算）是资金侧处置，28 天合计冻结或延迟约 33.6 万（合成金额单位，不对应任何货币）。助手在结论涉及它们时必须报出金额，并提示"误杀场次复核后解冻、需结算/财务知会"。

## 训练用的"变体世界"

为了后训练模型，原型还会生成 22 个变体世界（16 个训练、6 个测试）。策略库的结构不变，但每个世界里"哪个模型出问题、哪个市场召回下降、哪天流量暴涨、哪个公会出事"都不同；测试世界用了训练中从未出现的组合，用来检查模型学到的是方法，而不是背答案。

## 和真实策略库的差异

这些简化是有意的，合作方提问时可以直接说明：

- **规模小**：真实平台的策略可能有成百上千条，有多层编排、白名单、豁免和灰度；原型只有 29 条单层规则。
- **一种风险只有一个模型分**：真实情况下一条策略可能组合多个模型、多个特征和人工信号。
- **动作即时生效**：没有处罚升级链路（初犯警告、再犯封禁），也没有申诉后的恢复流程。
- **市场只有 6 个**：真实平台覆盖的市场更多，各地政策差异更大。
- **阈值和数字都是编的**：用来制造可识别的问题，不代表任何真实策略的合理取值。

如果合作方说"我们实际不是这样做的"，这正是最有价值的反馈：说明哪里不像，原型可以改策略库配置后重新生成数据，助手的方法不需要改。
